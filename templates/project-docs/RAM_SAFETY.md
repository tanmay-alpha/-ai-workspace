# RAM and Resource Safety Guide

> Guidelines for managing system resources during AI-assisted development.
> Generated by ai-workspace.

---

## Why This Matters

Running multiple large AI models, language servers, and development servers simultaneously
can exhaust RAM, cause CPU throttling, and corrupt in-progress work.

---

## One-Heavy-Agent-at-a-Time Rule

Only run one intensive AI process at a time:

| Heavy | Light (can run alongside) |
|---|---|
| Codex / OpenAI Codex CLI | Git operations |
| Gemini CLI (large context) | Text editors |
| Claude (API with large context) | Terminal commands |
| Local LLM (Ollama + large model) | Browser |
| n8n (complex workflows) | File explorers |

---

## Stop Heavy Tools When Switching

```powershell
# Stop known resource-heavy background processes
powershell -ExecutionPolicy Bypass -File scripts\stop-heavy-tools.ps1
```

---

## Warning Signs

- Fans running at full speed during coding sessions
- IDE becomes unresponsive
- Git operations suddenly slow
- Python/Node processes accumulating in Task Manager

---

## RAM Allocation Guidance

| Scenario | Recommended Available RAM |
|---|---|
| Local LLM (7B model) | 8 GB free |
| Local LLM (13B model) | 16 GB free |
| Codex + dev server + IDE | 4 GB free |
| Heavy Docker + API + AI | 8 GB free |

---

## Monitoring

```powershell
# Check memory usage
Get-Process | Sort-Object WorkingSet -Descending | Select-Object -First 15 Name, WorkingSet

# Kill a specific process
Stop-Process -Name "ollama" -Force
```

---

## Safe Session Pattern

1. Open IDE
2. Start ONE AI agent tool
3. Work until task complete
4. Stop the agent
5. Start the next agent if needed
